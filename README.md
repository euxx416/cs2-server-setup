# CS2服务器搭建：从挑 VPS 到开服跑通，SteamCMD、GSLT 和配置文件一次说清

搜索「CS2服务器搭建」的人，通常卡在同一个地方：不是不会敲命令，而是不知道该买什么机器。

有人拿 1核2G 的机器去装服务端，装到一半磁盘满了；有人机器买好了，服务端也起来了，但服务器列表里怎么都搜不到自己；还有人只算了月付价，没算国内机房独立 IP 和高防的钱，最后账单比预期翻了一倍。这些问题都不是"技术难"，而是信息没对齐。

下面按开服的实际顺序讲：需要什么配置、怎么装、端口怎么放、机房怎么选，以及在国内用雨云这类服务商落地时，具体该买哪一档。

## 先确定配置底线，别照着"最低要求"买机器

Valve 官方给 CS2 专服的最低要求是 Linux 2GB 内存、33GB 存储空间、glibc 2.31 以上（也就是 Ubuntu 20.04、Debian 11 或 Enterprise Linux 9 起步），CPU 至少 x86-64-v2 并支持 popcnt 指令集。

注意这是"能跑起来"，不是"能玩"。

实际承载人数对应的配置，第三方指南给的经验值是这样的：

| 服务器类型 | 人数 | Tick | CPU | 内存 | 存储 |
| --- | --- | --- | --- | --- | --- |
| Wingman / 小型练习服 | 2–10 | 64 | 2 vCPU | 4GB | 40GB SSD |
| 标准 5v5 | 10–24 | 64–128 | 4 vCPU | 6–8GB | 50GB NVMe |
| 社区服 / 多实例 | 24–64 | 128 | 6–8 vCPU | 16GB | 80GB NVMe |

Source 2 引擎的负载主要压在一条主线程上，所以挑机器时，单核性能比核心数更值得花钱。同样价格下，4 核高频通常比 8 核低频更适合 CS2 服——这一点在 CS:GO 时代就成立，CS2 没有改变这个逻辑。另一个容易忽略的硬约束是硬盘：服务端本体约 33GB，加上后续地图、插件、录像和更新缓存，40GB 可用空间是实际起点。Docker 镜像也明确要求至少 40GB 空闲磁盘。

很多人第一次开服失败就败在这里：买了 30GB 系统盘的机器，装完就剩几 G，更新一次直接爆盘。

## 服务端安装：SteamCMD + GSLT 两步不能省

CS2 的服务端和客户端已经合并成同一个 appid（730），不再是 CS:GO 时代那种客户端 730、服务端 740 分开的结构。

在 Linux 上，典型流程是这样：

bash
# 开启 32 位支持并装依赖
sudo dpkg --add-architecture i386
sudo apt update
sudo apt install -y lib32gcc-s1 wget curl

# 建一个独立用户（不建议用 root 跑）
sudo adduser --disabled-password --gecos "" csgo

# 用 SteamCMD 下载 730
./steamcmd.sh +login anonymous \
  +force_install_dir /home/csgo/cs2-server \
  +app_update 730 validate +quit


`validate` 用于首次安装或校验文件完整性；日常更新只跑 `app_update 730` 就够了。每次游戏版本更新后都要重跑一次，否则客户端连不上——这一步是 Valve 文档里明确要求的。

然后是最容易被忽略的一步：Game Server Login Token（GSLT）。没有有效 token，服务端会退回匿名模式，连接会被限制在局域网，公网玩家根本连不进来。申请入口在 Steam 的服务器管理页面（steamcommunity.com/dev/managegameservers），App ID 填 730，每个服务器实例需要一个独立 token，启动时用 `+sv_setsteamaccount <TOKEN>` 传入。

启动命令大概长这样：

bash
./cs2 -dedicated -port 27015 \
  +sv_setsteamaccount 你的GSLT \
  +game_type 0 +game_mode 1 \
  +map de_dust2 +maxplayers 10


`-dedicated` 不加就会当成客户端启动，这是新手常见的第一个坑。

## 端口、模式参数和 server.cfg

CS2 需要放行的端口不多，但有两个：

- **27015** UDP + TCP：游戏主端口（RCON 也走这个口的 TCP）
- **27020** UDP：SourceTV / CSTV，不打算做转播可以不开放

服务器类型由 `game_type` 和 `game_mode` 组合决定：

| 模式 | game_type | game_mode |
| --- | --- | --- |
| 休闲 | 0 | 0 |
| 竞技 5v5 | 0 | 1 |
| 搭档 2v2 | 0 | 2 |
| 死斗 | 1 | 2 |
| 自定义（滑翔、bhop 等） | 3 | 0 |

配置文件位置按安装方式不同：SteamCMD 装在 Linux 上是 `cs2-server/game/csgo/cfg/server.cfg`，Windows 下是 `C:\CS2-server\game\csgo\cfg\server.cfg`，Docker 则是挂载卷里的对应路径。

`server.cfg` 里至少要写清楚几件事：`hostname`（服务器名）、`rcon_password`（远程管理密码，别留默认值）、`sv_password`（公开服留空）、`sv_lan 0`、以及速率相关的 `sv_minrate` / `sv_maxrate` / `sv_mincmdrate` / `sv_maxcmdrate`。想跑 128 tick 的话，把服务端帧率相关参数和客户端速率参数一起往上调，两边不匹配照样丢包。

如果你不想手动折腾 SteamCMD，Docker 方案也成熟：直接用 `joedwards32/cs2` 镜像，通过环境变量配 `SRCDS_TOKEN`、`CS2_MAXPLAYERS`、`CS2_GAMETYPE`、`CS2_GAMEMODE`、`CS2_STARTMAP`、`TV_ENABLE` 这些，把 `/home/steam/cs2-dedicated` 挂出来做持久化就行。容器启动时会自动检查并更新游戏，官方要求最低 2 CPU / 2GiB 内存 / 40GB 磁盘。

## 国内开服，机房比配置更影响体验

同样一台 4核8G，放在香港和放在江苏，玩家体验是两回事。

CS2 是竞技 FPS，40ms 和 80ms 的差别玩家能直接感受到。国内玩家为主的服，物理位置在国内机房是首选。第三方测评里，雨云镇江 BGP 机型的实测三网延迟约 29ms，宿迁机型平均延迟约 31ms（最低 1ms），这个量级打竞技是能接受的。

第二个问题是防御。自建游戏服特别容易招 DDoS，尤其是人多起来之后。国内几家高防机房给的是百 G 级别的共享防御，独立 IP 还能独享整套防御——这也是为什么国内机房的独立 IP 单价比机器本身还贵。

第三是带宽。雨云游戏云 VPS 的上行带宽按档位卖，常见的是 5M / 10M / 15M，部分机型支持按 5Mbps 加购。CS2 本身不是带宽怪物，十几人的服,10M 上行通常够用，但如果你还挂着 SourceTV 转播、录像上传或者其他服务，就该往上留余量。

## 常见问题

**装服务端一定要 Linux 吗？**
不是，Windows 也能跑，Docker 方案同样可用。但 Linux 在内存占用和长期稳定性上更省心，社区教程也以 Ubuntu / Debian 为主。

**服务器列表里搜不到自己的服，先查什么？**
按顺序排查：GSLT 是否填对、`-dedicated` 是否带上了、27015 的 UDP 是否放行、服务器是否还在下载或更新文件。GSLT 无效会直接导致匿名模式并限制为局域网连接。

**NAT 机型能不能开 CS2 服？**
可以做端口映射，但对外 IP 和端口必须保持稳定，否则玩家收藏的地址会失效。打算长期运营、玩家数量持续增长的服，独立公网 IP 更省事。

**国内下载服务端很慢怎么办？**
SteamCMD 拉 33GB 文件时，国内网络可能要重试多次。可以在网络空闲时段执行更新，Docker 方案下重启容器会自动重试。

**动态计费和固定计费怎么选？**
看每天在线的时长。超过 2 小时选固定计费，低于 2 小时选动态计费，这是雨云游戏云两套计费模式的设计出发点。
